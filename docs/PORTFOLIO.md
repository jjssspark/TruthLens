# TruthLens — 포트폴리오 설명문

## 문제 정의

생성형 AI로 만들어진 이미지·영상·뉴스·논문이 빠르게 늘고 있는데, 일반 사용자가 그걸 스스로 확인할 도구는 마땅치 않습니다.
TruthLens는 이미지/영상/뉴스/논문을 올리거나 URL·텍스트로 넣으면 AI 생성 가능성을 점수와 근거(히트맵, 의심 문장, 인용 검증 등)로 보여주는 Flask 웹 서비스입니다.

팀 프로젝트로 시작한 코드베이스를, 기능을 더 붙이는 대신 "실제로 동작하고 설명할 수 있는 상태"로 만드는 데 집중해 개인 포트폴리오로 다듬었습니다.

## 이 프로젝트에서 제일 하고 싶은 이야기

영상 판별 기능을 만들고 나서 정확도를 직접 쟀는데, 아무것도 안 하고 무조건 "진본"이라고 답하는 것보다 못 나왔습니다.
그래서 지우지도 숨기지도 않고, 얼마나 못 맞히는지를 화면에 그대로 적었습니다. 과정은 이렇습니다.

### 1. 오탐 하나에서 시작

사람이 직접 찍은 12MB짜리 화면 녹화가 AI 62%로 나왔습니다.
원인을 찾아보니 영상 프레임을 `deepfake-detector-model-v1`에 넣고 있었는데, 이건 얼굴을 바꿔치기한 걸 잡는 모델이지 통째로 생성된 화면을 잡는 모델이 아니었습니다.
얼굴이 아예 없는 화면 녹화를 넣으면 답할 수 없는 질문을 던지는 셈이었습니다.

같은 사진 6장을 두 방식에 각각 넣어서 확인했습니다. 얼굴 조작 탐지기는 36~89% 사이에 몰려 답을 못 했고, 이미지 판별에 쓰던 3모델 앙상블은 0.3~99.8%로 갈렸습니다.
영상만 따로 모델을 쓸 이유가 없어서 이미지 쪽 앙상블 중앙값으로 갈아끼웠습니다. 그 영상은 62%에서 15.5%가 됐습니다.

같이 고친 것 — 샘플 프레임 16장을 6장으로 줄이고 뽑는 즉시 640px로 축소해 메모리를 300MB에서 10MB로, 판정 시간을 13.3초에서 6.1초로 줄였습니다.
근거가 없던 시간적 일관성 가중치(임계값을 넘으면 55점)는 점수에서 뺐습니다. 지극히 정상인 12초 클립도 이 규칙 때문에 점수가 흔들리고 있었습니다.

### 2. 고쳤다고 넘어가지 않고 재봤음

오탐 하나가 사라졌다고 잘 도는 건 아닙니다.
공개 데이터셋(deepaction_v1)에서 AI 생성 12개, 사람 촬영 15개를 받아 세 방식을 같은 프레임으로 채점했습니다.
추론 크레딧이 떨어져서 로컬에 모델을 받아 돌렸습니다.

| 방식 | 정확도 | AI를 AI로 | 진본을 진본으로 |
|---|---|---|---|
| 이미지 앙상블 (지금) | 37.0% | 4 / 12 | 6 / 15 |
| 얼굴 조작 탐지 (원래) | 37.0% | 9 / 12 | 1 / 15 |
| 픽셀 휴리스틱 | 55.6% | 0 / 12 | 15 / 15 |

기준선은 무조건 "진본"이라고 답하면 55.6%, 동전 던지기가 50%입니다. 만든 게 아무것도 안 하는 것보다 못합니다.
휴리스틱이 55.6%인 것도 실력이 아니라 AI를 하나도 못 잡아서 나온 숫자입니다.

측정이 잘못된 게 아닌지부터 확인했습니다. 원본 해상도로 다시 채점해도 같았고, 임계값을 20~80%로 훑어도 뒤집히지 않았고, 프레임을 눈으로 봐도 정상이었습니다.

### 3. 지우는 대신 못 믿는다고 적음

기능을 지우면 왜 안 되는지도 같이 사라지고, 안 되는 채로 두면 쓰는 사람을 속이는 게 됩니다.
그 사이에 "안 된다고 말하면서 남기는" 선택지가 있는데, 얼마나 안 되는지를 숫자로 알고 있어야 고를 수 있는 길입니다. 측정을 먼저 안 했으면 이 선택지 자체가 없었습니다.

- 업로드 화면에 경고를 먼저 띄웁니다. 결과를 보고 나서 "사실 못 믿는다"고 하면 늦습니다
- 결과에 실험적 배지와 함께 실측 37%, 기준선 55.6%를 그대로 적습니다
- "AI일 가능성이 높습니다" 같은 표현을 뺐습니다. 37%로는 그렇게 말할 수 없어서 본 것만 적기로 했습니다
- 이 문구가 슬그머니 사라지는 게 제일 흔한 회귀라 테스트 3개로 고정했습니다

대안 모델도 찾아봤습니다. 시공간 정보를 쓰는 연구(DeMamba, UNITE, DeCoF 등)는 활발한데 바로 가져다 쓸 배포 가중치가 없고, 허브에 올라온 건 얼굴 바꿔치기용이라 푸는 문제가 다릅니다.
지금 구조(프레임을 각각 사진으로 보기)로는 더 짜낼 게 없다는 것까지가 지금 아는 사실입니다.

### 4. 추측을 두 번 하고 나서 진단 창구를 만듦

배포본을 서버 로그만 보고 진단하다 두 번 틀렸습니다.
한 번은 제가 넣은 동시 호출 상한을 범인으로 지목했는데, 로그에 찍힌 문구가 옛 커밋의 것이라 그 코드는 배포된 적조차 없었습니다.
또 한 번은 크레딧이 떨어진 영향을 실제보다 크게 적었습니다. 나중에 모델별로 찔러보니 3개 중 2개는 멀쩡히 돌고 있었습니다.
둘 다 문서에서 지우지 않고 정정 이력을 그대로 남겼습니다.

그래서 `/diagnostics`를 열었습니다. 판별 코드 3개 파일의 내용 해시, 프레임 수 같은 실제 설정값, 모델이 지금 몇 개나 살아 있는지를 로그인 없이 밖에서 볼 수 있습니다.
비밀값은 안 담고 설정 여부만 참·거짓으로 줍니다. 값이 새지 않는지도 테스트로 고정했습니다.

## 그 밖의 기술적 판단

### 자체 API 규약을 코드가 실제로 지키게 함

`.claude/standards/api-contract.md`에 `{success, data, error}` 봉투를 정의해두고도 코드는 `{status, data, meta}`를 쓰고 있었습니다.
문서와 코드가 어긋난 상태를 두는 대신 `backend/api/response.py`의 `ok()`/`fail()`로 전 엔드포인트를 통일했습니다.
로깅도 구조화 JSON(`timestamp`/`level`/`message`/`traceId`/`service`)으로 바꾸고, `X-Request-Id`를 받아 `logging.Filter`로 전 계층에 자동 전파시켰습니다. 호출부마다 traceId를 넘기도록 기대하면 반드시 빠지기 때문입니다.

### 에러 처리를 라우트가 아니라 전역에서

모델 레벨에서만 예외를 감싸는 걸로는 부족하다는 걸 실제 버그(500 HTML 에러 페이지 노출)로 확인했습니다.
라우트마다 `try/except`를 흩뿌리는 대신 `app.py`에 전역 `errorhandler`를 등록해, 어디서 예외가 새더라도 응답에는 `INTERNAL_ERROR` 코드와 `traceId`만 나가고 스택 트레이스는 서버 로그에만 남게 했습니다.
외부 API 장애는 우리 서버의 버그가 아니라서 500이 아닌 502 `ANALYSIS_FAILED`로 구분합니다. 알림 기준을 나누기 위해서입니다.

### 업로드 경로의 path traversal 제거

초기 구현은 `file.filename`을 그대로 `os.path.join`에 넘겨서 `../../evil.jpg` 같은 이름이면 업로드 폴더 밖에 파일을 쓸 수 있었습니다.
`backend/services/upload_service.py`의 `save_upload()`로 일원화해 `secure_filename` + 확장자 allowlist + uuid 접두어를 적용했고, 취약점이 실재했다는 걸 증명하는 회귀 테스트를 남겼습니다.
uuid 접두어는 같은 이름 파일이 서로를 덮어쓰던 별개 버그도 같이 없앴습니다.

### 실 API로 검증

뉴스·논문 판별을 Mock이 아니라 실제 키로 테스트하면서 Mock으로는 안 드러나는 문제(DeepSeek 잔액 부족 402, DNS 장애 등)를 실제로 만났습니다.
논문 판별은 원래 DeepSeek이었는데 잔액이 떨어지면 402 하나로 기능이 통째로 멈춰서 Gemini로 옮겼습니다.

### 배포 장벽 낮추기

MariaDB/Redis 설치 없이 SQLite 폴백으로 로컬 실행이 되게 했고, `docker compose up` 한 줄이면 외부 설정 없이 뜨도록 구성했습니다.
MariaDB+Redis 조합이 필요하면 `--profile full`로 바꿉니다.

## 숫자

- 테스트 31개 → 178개, 커버리지 54% → 82% (backend + ai_models)
- 처음 clone 직후 31개 중 8개가 깨져 있던 걸 전부 통과로 만들고 이후 회귀 없이 유지
- 판별 로직부터 집중해서 채움 — `image_detector.py` 23% → 96%, `pixel_heuristics.py` 75% → 90%
- GitHub Actions에서 외부 API 키 없이 전체 스위트가 통과
- 트러블슈팅 28건을 증상·재현 조건·시도했지만 안 된 것·해결·검증으로 기록. 원인을 잘못 짚었던 2건은 정정 이력까지 남김
- 코드량 — 소스 3,515줄, 테스트 2,629줄, 화면 3,391줄, 측정 스크립트 291줄
