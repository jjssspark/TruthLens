TruthLens

AI가 만든 콘텐츠인지 판별해주는 웹 서비스

이미지·뉴스·논문·영상을 올리거나 URL·텍스트로 넣으면 AI가 만든 건지 점수랑 근거로 보여주는 Flask 웹 서비스임. 팀플로 만든 코드를 이어받아서, 기능을 더 붙이기보다 이미 있는 게 진짜로 돌아가는지 확인하는 데 시간을 씀.

01 / 08문제 정의

AI가 만든 건 늘어나는데, 확인할 방법이 없음

  • AI로 만든 영상·이미지·글이 빠르게 늘어나는 중임
  • 딥페이크로 가짜 정보를 퍼뜨리는 일이 실제로 생기고 있음
  • AI가 쓴 가짜뉴스나 논문 때문에 뭘 믿어야 할지 애매해짐
  • 그런데 일반 사용자가 직접 확인해볼 만한 도구는 딱히 없음
점수만 딸랑 보여주면 믿기 어려움. 왜 그렇게 나왔는지를 히트맵·EXIF·의심 문장으로 같이 보여주는 걸 기본으로 잡음.

그래서 뭘 했나

기능을 새로 붙이는 대신 되는지 확인하고, 보안 구멍 막고, 로그 남기고, 테스트 채우는 쪽만 하기로 함. 못 만든 부분은 슬쩍 넘어가지 않고 화면 배지랑 문서에 그대로 적어둠.

FR-01 영상은 두 가지 방식으로 돎

HF_TOKEN이 있으면 Hugging Face 추론 API의 딥페이크 모델로 프레임을 보고, 없으면 OpenCV로 픽셀을 직접 계산하는 쪽으로 넘어감. 어느 쪽으로 나온 결과인지는 details.method(hf-model / local-heuristic)에 항상 찍힘.

FR-04를 '부분'이라고 적은 이유

AI 비율·요약·PDF 리포트는 되는데, CitationService.analyze_citations()의 본문↔참고문헌 대조는 아직 TODO로 비어 있음. LLM이 뽑아준 인용 목록을 저장하는 데까지만 실제로 돎.

요청 흐름

Route→ Service→ Detector
Content Hash→ Cache→ DB 기록

라우트는 HTTP만, 서비스는 트랜잭션·캐시·집계만, 판별기는 분석만 맡도록 나눠둠. 캐시 키는 파일이면 SHA-256, 텍스트·URL이면 정규화해서 MD5로 만듦.

캐시를 두 가지로 씀

영상 · 이미지 · 논문→Redis · TTL 24h
뉴스→DetectionRequest 조회 · 7일

뉴스는 이력 통계(FR-05)랑 캐시 확인을 테이블 한 번 뒤지는 걸로 같이 처리할 수 있어서 기존 레코드를 그냥 재사용함. Redis가 없으면 캐시 미스로 넘어가서 기능 자체는 그대로 돎. 두 방식이 따로 노는 건 나중에 정리해야 할 부분임.

PRD 초안에는 Transformers · PyTorch · Alpine.js · Nginx도 적혀 있었지만 실제로 안 써서 뺐음

04 / 08판별 기법

어떻게 판별하는지

FR-02 이미지

픽셀 휴리스틱 3축 + EXIF

  • 노이즈 — 채널별 Laplacian 분산. 분산이 낮으면 AI 쪽으로 점수를 올림
  • 엣지 — Canny 엣지 밀도를 구간 나눠서 점수화
  • 색상 — 너무 고르게 퍼져 있는지 봄
  • piexif로 카메라·촬영일·소프트웨어를 꺼내고, EXIF가 아예 없으면 의심 표시
  • 의심 영역 히트맵을 base64로 만들어서 응답에 같이 실어보냄

API 키 없이 혼자 돌아가는 유일한 판별기임

FR-01 영상

프레임 뽑아서 모델 or 직접 계산

  • OpenCV로 최대 16프레임을 골고루 뽑고 224×224로 줄임
  • 모델 쪽은 한 장에 한 번씩 왕복이라 비용·쿼터 생각해서 8프레임까지만 씀
  • HF Router의 SigLIP 2-class 분류기를 부름. 모델마다 라벨 이름이 달라서 소문자로 바꿔 비교함
  • 프레임끼리 얼마나 튀는지 봐서 시간적 일관성도 같이 계산
  • 호출이 실패하면 직접 계산하는 쪽으로 넘어가고, 넘어갔다는 걸 결과에 남김
FR-03 뉴스

Gemini한테 한 번에 물어봄

  • AI가 썼는지 · 가짜뉴스일 가능성 · 출처 신뢰도 · 논리성 · 과장 표현 · 의심 문장을 한 번에 받아옴
  • URL로 넣으면 BeautifulSoup4로 본문만 긁어서 넘김
  • 모델을 gemini-2.5-flash-lite로 바꿔서 같은 프롬프트가 약 16초 → 1.3초가 됨

쓰고 있는 구 SDK가 thinking_config를 안 받아서 추론을 끌 방법이 없었음. 모델을 바꾸는 걸로 우회함

FR-04 논문

PDF 뜯어서 LLM 태우고 리포트로

  • pypdf로 텍스트를 뽑고 DeepSeek(OpenAI SDK 호환)에 판정을 맡김
  • 결과를 reportlab으로 리포트 PDF로 만들어줌
  • 한글 폰트는 캐시 → 시스템 폰트 → 다운로드 순으로 찾음
  • 셋 다 실패하면 KoreanFontUnavailable을 던지고 멈춤

폰트 없이 만들면 한글이 전부 네모로 나옴. 깨진 PDF를 조용히 내보내느니 그냥 실패시키는 게 낫다고 봄

05 / 08고민했던 것들

왜 이렇게 했나

API Contract

정해둔 응답 형식을 코드가 실제로 지키게 함

문제
문서엔 {success, data, error}라고 써놓고 코드는 {status, data, meta}를 쓰고 있었음
결정
backend/api/response.py의 ok()/fail()로 전부 통일
결과
data랑 error 중 하나는 항상 null이라, 프론트가 code만 보고 분기하면 됨
Resilience

에러 처리를 한 곳에서 몰아서 함

문제
라우트가 서비스 예외를 못 잡아서 500 HTML 에러 페이지가 그대로 보였음
결정
라우트마다 try/except를 뿌리는 대신 app.py에 errorhandler 하나만 등록
결과
응답엔 INTERNAL_ERROR랑 traceId만 나가고 스택은 서버 로그에만 남음. 외부 API가 죽은 건 내 잘못이 아니라서 502 ANALYSIS_FAILED로 따로 뺌
Security

업로드 경로 path traversal 막음

문제
file.filename을 그대로 os.path.join에 넘기고 있어서, ../../evil.jpg 같은 이름이면 업로드 폴더 밖에 파일을 쓸 수 있었음
결정
업로드를 save_upload() 하나로 모으고 확장자 allowlist + secure_filename + uuid 접두어를 붙임
결과
진짜로 뚫렸다는 걸 보여주는 테스트를 같이 남겼고, 같은 이름 파일이 서로 덮어쓰던 버그도 덤으로 잡힘
Observability

traceId를 매번 안 넘겨도 되게 함

문제
로그 찍는 곳마다 traceId를 챙겨 넘기라고 하면 어디선가 반드시 빠짐
결정
X-Request-Id를 before_request에서 받아두고 logging.Filter가 모든 로그에 알아서 붙이게 함
결과
로그가 JSON(timestamp/level/message/traceId/service)으로 나감. 비밀번호·토큰은 로거에서 강제로 가리고, 요청 컨텍스트가 없는 Celery 워커에서도 안 터짐
Honesty

폴백했으면 폴백했다고 적음

문제
직접 계산한 결과를 모델이 판정한 걸로 착각할 수 있었음
결정
어느 쪽으로 나왔는지를 details.method에 항상 남기고, Redis가 없거나 모델 호출이 실패한 것도 로그로 찍음
결과
모델 쓴 척을 안 하게 됨. 이 결과를 얼마나 믿을지는 보는 사람이 판단하면 됨
Deployment

일단 받아서 돌려볼 수 있게 만듦

문제
MariaDB랑 Redis부터 깔아야 하면 아무도 안 돌려봄
결정
없으면 SQLite로 떨어지게 하고 뜰 때 db.create_all()이 알아서 돌게 함. docker compose up 한 줄로도 뜸
결과
clone 받고 3분이면 실행됨. MariaDB+Redis로 돌리고 싶으면 --profile full만 붙이면 됨
06 / 08트러블슈팅

고치면서 적어둔 것 중 몇 개

STABILITY

API 키가 없으면 서버 자체가 안 켜졌음. → PaperDetector 생성자에서 키를 검사하고 있어서, 앱 뜰 때 바로 터졌음. 검사를 실제로 쓸 때로 미뤄서 키가 없어도 앱은 뜨고 논문 기능만 에러를 내게 바꿈.

SECURITY

비밀번호가 평문 그대로 저장되고 평문끼리 비교되고 있었음. → werkzeug.security의 generate_password_hash / check_password_hash로 갈아끼움.

API

DeepSeek 402(잔액 부족) 에러 원문이 사용자 화면에 그대로 떴음. → _friendly_error_message()에서 402·429·401을 한국어 문장으로 바꿔주고, 원문은 서버 로그에만 남기게 함.

DATA

분석이 실패했는데 "AI 가능성 0%"라는 결과처럼 저장되고, 그게 캐시에까지 들어갔음. → 판별기가 details.error로 조용히 돌려주던 실패를 PaperAnalysisError로 올려서, 실패는 실패로 남기고 캐시에는 안 들어가게 막음.

INFRA

어제 커밋한 UI 변경이 docker compose up 화면에 하나도 안 보였음. → 코드 문제인 줄 알고 한참 봤는데, 이미지 생성 시각이랑 git 커밋 시각을 대조해보니 13일 전 이미지를 그대로 쓰고 있었음. --build로 다시 굽고 실행 안내 문서도 고침.

CI

PDF 한글 폰트 테스트가 한쪽 환경에서만 실패함. → OS마다 잡히는 폰트가 달라서(맥은 AppleGothic, CI는 나눔고딕) 폰트 이름으로 검사하면 어긋났음. TrueType이 실제로 PDF에 박혔는지(/FontFile2)만 보도록 바꿔서 환경을 안 타게 함.

UI

320px 화면에서 결과 게이지가 카드 밖으로 삐져나갈 조건이었음. → 페이지 패딩 + 카드 패딩 + 고정폭을 직접 더해보고 넘치는 걸 확인한 뒤 width: min(280px, 100%)로 고침.

전체 12건은 docs/TROUBLESHOOTING.md에 있음 — 어떻게 재현했는지, 뭘 해봤다가 안 됐는지까지 같이 적어둠

08 / 08배포 · 남은 것

배포는 이렇게, 못 한 건 이만큼

어떻게 배포하나

dev→ qa→ main · 자동 배포

클라우드타입(cloudtype.io)에 올림. Flask App(Gunicorn) · Celery Worker · MariaDB · Redis를 한 프로젝트 안에 두고 서비스명으로 서로 부르게 했고, GitHub 연동해서 푸시하면 알아서 빌드·배포됨. 프록시 뒤에 있으면 https URL이 http로 만들어지길래 ProxyFix를 붙임. 키 같은 건 코드에 안 두고 플랫폼 환경 변수로 넣음.

지금 돌아가는 데모

무료 티어라 컨테이너가 재시작되면 가입한 계정이나 올린 파일이 날아갈 수 있음. 이미지 판별은 키 없이 바로 눌러볼 수 있음.

아직 못 한 것

  • 영상 판별 — HF_TOKEN이 없으면 픽셀 계산으로만 돌아감. 시중에 나온 딥페이크 탐지만큼 정확하진 않음
  • 인용 교차 검증 — 본문이랑 참고문헌을 맞춰보는 부분, 빠진 인용을 찾아주는 부분은 아직 안 만들었음
  • Tailwind CDN — 공식 문서가 실서비스에 쓰지 말라는 개발용 스크립트를 그냥 쓰고 있음. CLI 빌드로 바꾸려면 forms·container-queries 플러그인을 옮기고 폼이 안 깨지는지 봐야 함
  • 캐시 — 뉴스만 DB를 쓰고 있어서 TTL이나 무효화 규칙이 두 군데로 흩어져 있음

다음에 할 것

  • 뉴스도 Redis로 옮겨서 캐시 규칙을 한 군데서 보게 하기
  • 인용 교차 검증 만들고 DOI로 메타데이터 찾아오기
  • Tailwind CLI 빌드로 바꿔서 CDN 떼기
안 되는 걸 되는 척하는 것보다, 못 한 걸 못 했다고 적는 게 낫다고 생각함.
