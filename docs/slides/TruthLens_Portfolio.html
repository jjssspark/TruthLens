TruthLens

AI 생성 콘텐츠 판별 웹 서비스

이미지·뉴스·논문·영상을 업로드하거나 URL·텍스트로 입력하면 AI 생성 가능성을 점수와 근거로 제시하는 Flask 웹 서비스임. 팀 프로젝트 코드베이스를 기능 추가가 아니라 "실제로 동작하고 설명 가능한 상태"로 만드는 데 집중해 개인 포트폴리오로 고도화함.

01 / 08문제 정의

판별 도구 없이 AI 생성물만 범람하는 상태

  • 생성형 AI 확산으로 AI 생성 영상·이미지·텍스트(뉴스·논문)가 급증하는 상황임
  • 딥페이크 영상·이미지를 이용한 허위정보 유포가 발생함
  • AI 생성 가짜뉴스·논문으로 인한 여론 조작 및 학술 신뢰성 훼손이 문제임
  • 일반 사용자가 콘텐츠의 AI 생성 여부를 스스로 판단할 도구가 부재함
판별 결과를 점수 하나로 던지는 대신, 왜 그렇게 판정했는지를 히트맵·EXIF·의심 문장으로 함께 제시하는 것이 설계 전제임.

고도화 방향

신규 기능을 늘리는 대신 동작 검증 · 보안 결함 제거 · 관측성 확보 · 테스트 확충으로 범위를 한정함. 구현하지 못한 부분은 감추지 않고 UI 배지와 문서에 한계로 명시하는 방침을 택함.

FR-05 캐싱·집계 콘텐츠 해시 재분석 회피, 캐시 배지, 분석 요청자 수 불필요 동작

FR-01 — 두 갈래로 동작

HF_TOKEN이 있으면 Hugging Face 추론 API의 딥페이크 분류 모델로 프레임을 판정하고, 없으면 OpenCV 픽셀 휴리스틱으로 폴백함. 어느 쪽을 썼는지는 결과의 details.method(hf-model / local-heuristic)에 항상 표기됨.

FR-04 — 부분 구현으로 표기하는 이유

AI 생성 비율·요약·PDF 리포트는 동작하나, CitationService.analyze_citations()의 본문↔참고문헌 교차 검증은 TODO 스텁 상태임. LLM이 추출한 인용 목록을 저장하는 단계까지만 실제로 동작함.

요청 흐름

라우트는 HTTP만, 서비스는 트랜잭션·캐시·집계만, 판별기는 순수 분석만 담당하도록 책임을 분리함. 캐시 키는 파일 SHA-256, 텍스트·URL은 정규화 후 MD5로 생성함.

캐싱 이원화

영상 · 이미지 · 논문→Redis · TTL 24h
뉴스→DetectionRequest 조회 · 7일

뉴스는 이력 통계(FR-05)와 캐시 판단을 한 번의 테이블 조회로 처리 가능해 기존 레코드를 재사용함. Redis 부재 시 캐시 미스로 처리되어 기능 자체는 정상 동작함. 두 방식이 통일되지 않은 점은 알려진 기술 부채임.

PRD 원안에 있던 Transformers · PyTorch · Alpine.js · Nginx는 실제 구현에 포함되지 않아 제외함

04 / 08판별 기법

도메인별로 실제 적용한 분석 방식

FR-02 이미지

픽셀 휴리스틱 3축 + EXIF

  • 노이즈 균일도 — 채널별 Laplacian 분산, 분산이 낮을수록 AI 가능성 상향
  • 엣지 매끄러움 — Canny 엣지 밀도를 구간별로 점수화
  • 색상 분포 — 과도한 균형 여부 판정
  • piexif로 카메라·촬영일·소프트웨어 추출, EXIF 부재 시 의심 플래그
  • 의심 영역 히트맵을 base64로 인코딩해 응답에 동봉

외부 API 키 없이 단독 동작하는 유일한 판별기임

FR-01 영상

프레임 샘플링 + 모델·휴리스틱 이중 경로

  • OpenCV로 최대 16프레임 샘플링, 224×224 리사이즈
  • 모델 경로는 왕복 비용·쿼터를 감안해 최대 8프레임으로 제한
  • HF Router 추론 API의 SigLIP 2-class 분류기 호출, 모델별 라벨 표기 차이는 소문자 집합 비교로 흡수
  • 프레임 간 변화량으로 시간적 일관성을 추가 분석
  • 호출 실패 시 휴리스틱으로 폴백하고 그 사실을 결과에 기록
FR-03 뉴스

Gemini 구조화 판정

  • AI 생성 여부 · 가짜뉴스 가능성 · 출처 신뢰도 · 논리성 · 과장 표현 · 의심 문장을 한 번에 판정
  • URL 입력은 BeautifulSoup4로 본문을 추출한 뒤 전달
  • 모델을 gemini-2.5-flash-lite로 선택해 동일 프롬프트 기준 약 16초 → 1.3초로 단축

구 SDK는 thinking_config를 지원하지 않아 내부 추론을 끌 수 없으므로 모델 선택으로 해결함

FR-04 논문

PDF 파싱 + LLM + 리포트 생성

  • pypdf로 텍스트를 추출한 뒤 DeepSeek(OpenAI SDK 호환)에 판정 요청
  • reportlab으로 분석 리포트 PDF 생성
  • 한글 폰트는 시스템 폰트 → 캐시 → 원격 다운로드 3단 폴백
  • 폰트 확보 실패 시 KoreanFontUnavailable로 명시적 실패

폰트 없이 생성하면 한글이 전부 네모로 나오므로, 깨진 산출물을 조용히 내보내는 대신 실패시키는 쪽을 택함

05 / 08기술적 의사결정

여섯 가지 판단과 근거

API Contract

응답 봉투를 코드가 실제로 지키게 함

문제
규약은 {success, data, error}인데 코드는 {status, data, meta}를 쓰고 있었음
결정
backend/api/response.py의 ok()/fail()로 전 엔드포인트 통일
효과
data·error 중 한쪽은 항상 null이 되고, 프론트가 code로 분기 가능해짐
Resilience

에러 처리를 전역 계층에서 보장함

문제
라우트가 서비스 예외를 놓쳐 500 HTML 에러 페이지가 그대로 노출됨
결정
app.py에 전역 errorhandler를 등록해 라우트별 try/except 산재를 제거
효과
응답엔 INTERNAL_ERROR와 traceId만 나가고 스택은 서버 로그에만 남음. 외부 API 장애는 502 ANALYSIS_FAILED로 구분해 알림 기준을 분리함
Security

업로드 경로의 path traversal을 제거함

문제
file.filename을 sanitize 없이 os.path.join에 넘겨 ../../evil.jpg로 폴더 밖 쓰기가 가능했음
결정
save_upload() 단일 진입점에 확장자 allowlist + secure_filename + uuid 접두어 적용
효과
취약점 실재를 증명하는 회귀 테스트를 함께 남기고, 동명 파일 덮어쓰기 버그도 동시 해소함
Observability

traceId 전파를 호출부에 맡기지 않음

문제
호출부마다 traceId를 넘기도록 기대하면 반드시 누락됨
결정
X-Request-Id를 before_request에서 받아 logging.Filter로 전 레코드에 주입
효과
구조화 JSON 로그(timestamp/level/message/traceId/service) 출력. 비밀값은 로거 레벨에서 강제 리댁션되고, 요청 컨텍스트가 없는 Celery 워커에서도 예외 없이 동작함
Honesty

폴백을 조용히 넘기지 않음

문제
휴리스틱 결과를 모델 판정으로 오인할 여지가 있었음
결정
판정 방식을 details.method에 항상 기록하고, Redis 부재·모델 호출 실패도 로그로 남김
효과
모델을 쓴 척하지 않게 되고, 결과의 신뢰 구간을 사용자가 스스로 판단 가능해짐
Deployment

실행 진입장벽을 낮춤

문제
MariaDB·Redis 설치가 로컬 실행의 장벽이었음
결정
SQLite 폴백 + 기동 시 db.create_all() 자동 실행, docker compose up 한 줄 기동
효과
신규 clone 기준 3분 내 실행 가능. MariaDB+Redis 구성은 --profile full로 선택 전환함
06 / 08트러블슈팅

증상 → 원인 → 해결, 12건 중 발췌

STABILITY

API 키가 없으면 서버 자체가 부팅되지 않음. → PaperDetector 생성자에서 수행하던 키 검증을 실제 호출 시점으로 이동, 키 없이도 앱이 기동되고 해당 기능만 실패하는 graceful degradation으로 전환함.

SECURITY

비밀번호가 평문으로 저장·비교되고 있었음. → werkzeug.security의 generate_password_hash / check_password_hash로 교체함.

API

DeepSeek 402(잔액 부족) 원본 에러가 사용자에게 그대로 노출됨. → _friendly_error_message()로 402·429·401을 한국어 메시지로 변환하고 원문은 서버 로그에만 남김.

DATA

판별 실패가 "AI 생성 가능성 0%" 판정처럼 저장되고 캐시에까지 유입됨. → 판별기가 details.error로 돌려준 실패를 PaperAnalysisError로 승격해, 실패를 실패로 기록하고 캐시 저장을 차단함.

INFRA

docker compose up이 13일 전 이미지를 재사용해 최신 커밋이 반영되지 않음. → 이미지 생성 시각과 git 커밋 시각을 대조해 원인을 확정하고 --build 재빌드로 해결, 실행 안내 문서를 갱신함.

CI

PDF 한글 폰트 테스트가 CI에서만 실패함. → CI 러너에 한글 폰트가 없어 폴백 경로가 달라진 것이 원인. 캐시 공유 방식과 검증 문자열을 환경 비의존적으로 수정함.

UI

320px 모바일에서 결과 게이지가 카드 밖으로 넘칠 조건이었음. → 페이지 패딩 + 카드 패딩 + 고정폭 요소를 직접 계산해 검증한 뒤 width: min(280px, 100%)로 수정함.

전체 12건은 docs/TROUBLESHOOTING.md — 재현 조건과 시도했지만 실패한 방법까지 포함해 기록함

08 / 08배포 · 남은 과제

배포 구성과 알려진 한계

배포 파이프라인

dev→ qa→ main · 자동 배포

클라우드타입(cloudtype.io) 기반. Flask App(Gunicorn) · Celery Worker · MariaDB · Redis를 프로젝트 내 서비스명으로 상호 통신시키며, GitHub OAuth 연동으로 브랜치 푸시 시 자동 빌드·배포됨. 리버스 프록시 뒤에서 https URL이 정상 생성되도록 ProxyFix를 적용함. 민감 정보는 코드에 두지 않고 플랫폼 환경 변수로 관리함.

라이브 데모

무료 티어 컨테이너로 운영 중이며, 재시작 시 가입 계정·업로드 데이터가 초기화될 수 있음. 이미지 판별은 API 키 없이 즉시 체험 가능함.

알려진 한계

  • 영상 판별 — HF_TOKEN 없이는 휴리스틱 모드이며, 상용 딥페이크 탐지 수준의 정확도가 아님
  • 인용 교차 검증 — 본문↔참고문헌 대조와 누락 인용 메타데이터 검색은 미구현 상태임
  • Tailwind CDN — 공식 문서가 프로덕션 사용을 권장하지 않는 개발용 스크립트를 사용 중임. CLI 빌드 전환 시 forms·container-queries 플러그인 이관과 폼 스타일 회귀 확인이 필요함
  • 캐시 이원화 — 뉴스만 DB 캐시라 TTL·무효화 정책이 한 곳에서 관리되지 않음
